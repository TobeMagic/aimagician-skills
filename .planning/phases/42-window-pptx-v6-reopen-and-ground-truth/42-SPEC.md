# Phase 42 Specification — v6.1 quality recovery contract

## Objective

Replace the synthetic v6 completion story with an evidence-bound pipeline:

```text
realistic locked brief
→ authenticated private catalog acquisition
→ safe package inventory and page-level visual mining
→ certified complete-work spine plus compatible supplemental pages
→ TemplateSelectionPlan and SlideBlueprint
→ physical-template/native-composition materialization
→ editable PPTX and rendered evidence
→ deterministic QA and bounded repair
→ three fresh independent visual reviews
→ GO or fail-closed
```

## Delivery phases

### Phase 42 — Reopen and ground truth

Correct planning state, requirements, documentation, and acceptance semantics.
Freeze the implementation and verification plan through an independent
OpenCode plan review.

### Phase 43 — Real Playwright acquisition

Implement an authenticated, resumable, same-origin Gaojie source adapter. It
must enumerate all requested categories and pages, discover product/detail
links, download entitled packages, content-address them, preserve provenance,
deduplicate, and fail safely on login expiry, unsafe redirects, unsupported
packages, low disk space, or site changes. Provide a local browser fixture that
proves login-state handling, pagination, download, resume, dedupe, and secret
redaction without needing the external account.

### Phase 44 — Private asset intelligence

Passively inventory PPTX/PPT/POTX/ZIP packages; quarantine active or unsafe
content; render decks and page thumbnails; extract page-level geometry, object,
font, color, image, chart, table, and semantic-role features; cluster complete
works and supplemental pages; create searchable local indexes; certify a core
300–500 page library with rights and safety evidence.

### Phase 45 — Selection-to-materialization bridge

Make the production generator consume the exact `TemplateSelectionPlan` and
`SlideBlueprint`. Physical candidates must route through the TemplatePack
adapter or a page-composition transplant that preserves design dependencies.
Registered compositions route through the governed native renderer. Unknown,
uncertified, incompatible, or unmaterialized candidates fail closed. Every
output records selected candidate IDs and actual materializer evidence.

### Phase 46 — Three reference-grade anchors

Regenerate the work report, campus competition defense, and academic defense
from complete realistic briefs and actual certified visual candidates. Each
deck must contain a functional cover, directory, section dividers, evidence
body, decision/conclusion, closing, and appendix; use scenario imagery,
editable charts/tables/diagrams, purposeful page rhythm, and a coherent visual
spine.

### Phase 47 — Fifteen scenarios and ordinary-model mode

Expand template and rule coverage to the full realistic corpus. Constrain
ordinary models to narrative grouping, candidate choice, and slot binding.
Measure schema success, selection validity, repair rate, editability, visual
quality, and reproducibility against the strong-author baseline.

### Phase 48 — Blind acceptance and closure

Generate anonymous, hash-bound review packets with full-resolution pages and
contact sheets. Three fresh visual-capable AI contexts review every anchor.
Any independent `Blocker` or `Important` finding blocks the candidate. Final
closure also requires a fresh nonvisual OpenCode completion audit covering
every latest user request, implementation, test, artifact, and Git state.

## Non-goals

- No access-control bypass or secret persistence outside `.private/`.
- No claim that category counts or code variants equal real template counts.
- No whole-slide raster delivery.
- No requirement that PowerPoint COM be available for normal generation.
- No unlimited repair loop or decorative patch accumulation.
- No release claim from structural metrics or unit tests alone.

## Completion rules

The milestone remains open when authentication has not been exercised, no real
private templates have been acquired, the generator does not materialize its
selected candidates, any anchor lacks fresh pixel review, or any independent
reviewer reports an unresolved `Blocker` or `Important` finding.
