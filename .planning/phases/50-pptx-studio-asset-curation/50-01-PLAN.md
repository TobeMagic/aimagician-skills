# Phase 50: Asset Curation and Visual Catalog - Plan 01

**Created:** 2026-08-11
**Requirements:** V7-CURATE-01, V7-CATALOG-01, V7-VISION-01, V7-REGION-01, V7-QUERY-01
**Requests:** USR-V7-01
**Status:** Approved

## Objective

Create a reversible active/private-library boundary and prove one end-to-end
catalog tracer: allowlisted private sources → portable pages → hash-bound visual
observations + safe regions → deterministic bounded query. Do not change
production generation or package identity in this phase.

## Non-Goals

- Actual component import/adaptation and page/deck composition (Phase 51).
- `pptx-studio` public migration, deleting `window-pptx`, installed sync, full
  quality harness and clean-room generation (Phases 52–53).
- Private source deletion, public asset distribution, unbounded visual upload
  or model-authored layout/OOXML/code.

## Tasks

### Task 1: Freeze active/archive source scope and recovery contract

**Requirements:** V7-CURATE-01
**Depends on:** None
**Slice:** Tracer
**Allowed files:** new `skills/owned/window-pptx/scripts/pptx_studio/curation.py`,
`schemas/active-source-scope.v1.schema.json`,
`schemas/curation-manifest.v1.schema.json`, CLI wiring and
`tests/window_pptx/test_pptx_studio_curation.py`.
**Forbidden files:** private source content until dry-run tests pass; legacy
physical assembler; public `SKILL.md`; source/install paths.

1. Add fixtures with approved, inactive, missing, duplicate and path-escape
   categories; make `plan_curation` fail before an exact partition exists.
2. Implement the closed 22-category allowlist, stable manifest, per-file/tree
   SHA-256 evidence, dry-run, apply, verify and recover-dry-run modes. Every
   inactive package record carries opaque ID, original/archive relative
   locators, pre/post SHA-256, parent tree digests and exact hash-guarded
   recovery operation; missing any field fails before move.
3. Probe the actual original private root in dry-run only; inspect counts,
   hashes and proposed archive paths before invoking apply.
4. Apply only after plan review/execution gate; verify both archive partition
   and recovery feasibility without moving anything back.

**Acceptance:** V7-CURATE-01, GOAL-50-01, AC-50-01/02.
**Integration points:** explicit private-root resolver, ignored private
`archive/pptx-studio/` state.
**Checkpoint:** Persist private manifest path/digest and confirm active sources
were untouched before starting catalog compilation.

### Task 2: Compile deterministic deck/page catalog and safe OOXML regions

**Requirements:** V7-CATALOG-01, V7-REGION-01
**Depends on:** Task 1 verified active scope
**Slice:** Boundary
**Allowed files:** `scripts/pptx_studio/catalog.py`,
`scripts/pptx_studio/regions.py`, versioned catalog/region schemas, CLI and
`tests/window_pptx/test_pptx_studio_catalog.py`,
`tests/window_pptx/test_pptx_studio_regions.py`.
**Forbidden files:** legacy v6.1 APIs/tests, public Skill and archive payload.

1. Create failing synthetic PPTX/OOXML fixtures for duplicate page identity,
   root escape, unrendered image, image-only region, unsafe shape group and
   overlapping candidate regions.
2. Compile active package/page records from the scope plus portable evidence;
   stable IDs use source hash/slide/region name—not private filename.
3. Extract source shape geometry and text capacity, then produce only safe
   region candidates; visual labels must remain unset until Task 3.
4. Assert repeat output byte equality and schema validation. Run a private
   smoke compile after Task 1 apply and inspect only summary/digests locally.

**Acceptance:** V7-CATALOG-01, V7-REGION-01, GOAL-50-02/04, AC-50-03/05.
**Integration points:** existing portable render evidence, private catalog
root, no query file discovery.
**Checkpoint:** Record page/region count, exclusions and catalog digest.

### Task 3: Acquire and validate visual observations through Agnes

**Requirements:** V7-VISION-01
**Depends on:** Task 2 catalog/page image hashes
**Slice:** AI boundary
**Allowed files:** visual-observation schema, `observations.py`, batch driver,
fixed prompt, tests and private visual-observation output.
**Forbidden files:** any original PPTX/media upload, credential logging,
model-written geometry/fact/code, public tracked observation output.

1. Write failing observation fixtures covering hash mismatch, missing required
   uncertainty, unexpected field, malformed response, and one negative egress
   case for each prohibited class: source path, source/package/category name,
   PPTX/media byte or encoding, credential-like key, and unregistered field.
2. Implement strict normalization/validation, a private
   `opaque_page_id -> PNG/hash` mapping and resumable batch selection by image
   hash. Egress validation rejects source locators/names, PPTX/media bytes,
   credentials and unknown fields in request and response; store
   provider/model/prompt digest and only sanitized fields.
3. Use `vision-analysis` against rendered active-page PNGs in batches of at
most eight, explicitly with the user-authorized upload flag; retries follow
the Skill's rate-limit policy.
4. Locally inspect representative contact sheets (cover, directory, section,
content, people, timeline, process, excellent work) against the observations;
mark uncertainty rather than repairing model prose silently.

**Acceptance:** V7-VISION-01, GOAL-50-03, AC-50-04.
**Integration points:** hash-bound catalog page record; private local JSONL or
JSON index only.
**Checkpoint:** Record observation coverage, unavailable count and sample
spot-check identities/digests, without publishing image paths or content.

### Task 4: Deliver deterministic bounded retrieval tracer

**Requirements:** V7-QUERY-01
**Depends on:** Tasks 2–3 complete catalog records
**Slice:** End-to-end tracer
**Allowed files:** `query.py`, query schema/CLI, focused tests and private
catalog query smoke evidence.
**Forbidden files:** client-folder scanners, live model call from query,
legacy page-query behavior changes, assembly or Skill migration.

1. Add failing tests for invalid reuse mode, unapproved category, missing
observation, capacity/style mismatch, over-limit request and client-root
locator attempt.
2. Implement `deck`, `page`, and `region` modes with fixed eligibility gates,
   scoring components and a 3–6 default bounded response containing reasons;
   equal scores sort by stable catalog ID ascending as final tie-break.
3. Compile/query the actual active catalog through an explicit private root;
   repeat query serialization and verify no source tree walk occurs.
4. Produce a small retrieval UAT packet for later Phase 51: sample requests
   for cover, directory, section, 3-item content, team, timeline, process,
   business model, map and closing.

**Acceptance:** V7-QUERY-01, GOAL-50-05, AC-50-06.
**Integration points:** Phase 51 composition selector consumes query schema.
**Checkpoint:** Record exact query/catalog digest and candidate summaries only.

## Rollback And Recovery

- Before archive apply: discard only the generated private dry-run plan; no
  source moved.
- After archive apply: use hash-verified `recover --dry-run`, then `recover`
  only for exact matching archive records. A mismatch stops and retains both
  trees for manual inspection.
- Code rollback is a normal Git revert. Phase 50 never changes existing
  production generation behavior or installs a renamed Skill.
