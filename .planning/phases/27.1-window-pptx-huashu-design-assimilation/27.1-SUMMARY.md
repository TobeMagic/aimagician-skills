# Phase 27.1 Implementation Summary

> **Supersession note (2026-07-21):** This summary preserves what Phase 27.1 implemented. Phase 27.2 later makes PptxGenJS the governed daily renderer, adds OOXML and LibreOffice hard gates, and moves PowerPoint to explicit legacy use plus sampled certification. The 505-test result and Recording-COM calibration remain historical pre-27.2 evidence.

## Outcome

The ordinary-model default route is now a constrained authority chain:

`trusted sources -> immutable FactStore -> restricted BriefPlan -> deterministic NarrativePlan -> canonical DeckPlan -> art direction/theme/layout -> native RenderPlan -> quality v2 -> bounded repair`

The model groups fact IDs and chooses registered hints. It no longer owns factual prose, coordinates, colors, fonts, template IDs, or arbitrary visual rules. Direct DeckPlan remains an explicit expert/replay compatibility route.

## Implemented Systems

- Strict FactStore, BriefPlan, NarrativePlan, BrandSpec, direction, quality-v2, repair-log, fingerprint, and benchmark schemas.
- Executable critical-beat rules for all 15 supported commercial archetypes.
- At most two BriefPlan retries followed by a deterministic fact-safe default.
- Twelve independently authored neutral art directions and deterministic safe/editorial/expressive candidates.
- Brand asset/font/color/pattern hard gates, six semantic brand colors, persisted theme-resolution evidence, BrandSpec/font/asset provenance hashes, safe PNG/JPEG/passive-SVG preflight, and native statement fallback.
- Deterministic geometry variants, art-direction-aware but semantics-safe layout ranking, and semantic-form-authoritative native charts.
- Input/narrative/compile/render/preview/package/editability quality namespaces, anti-slop checks, mandatory pre-save PNG preview gates for the Brief route, one pre-render repair, one post-render repair, canonical protected-content rollback, and save-time candidate reinspection.
- Explicit OOXML save formats for PPTX/PPTM/POTX/POTM, pre-COM evidence persistence, and post-save reopen validation of editable text, tags, charts, tables, and diagrams before atomic promotion.
- Progressive Skill guidance and five focused reference documents.
- Six same-input calibration cases and a re-frozen 180-trial ordinary-model protocol whose full-v5 arm accepts only BriefPlan.
- Complete fingerprint-bundle schema with typed, hash-bound dependency/provider/Windows/font/PowerPoint/asset component manifests, plus a release gate rejecting missing, dirty, placeholder, pre-Huashu, mixed, artifact-mismatched, invalid-response, or threshold-failing evidence.
- Blind-review packets remain unscorable until a readable OOXML PPTX and byte-verified PNG evidence are hash-checked and atomically staged under anonymized `B-*` review paths.

## Huashu Assimilation Boundary

Adopted principles include story-before-layout, three distinct directions, two proof pages, asset/brand discovery before palette, content-derived motifs, anti-slop critique, and concept/content fit. They were independently implemented in the native PowerPoint architecture.

Rejected items include the HTML-to-PPTX runtime, copied prompts or named styles, random time-based selection, bundled media/fonts, placeholder delivery, and prompt-only quality gates. The pinned reference and MIT notice are recorded; no Huashu runtime code or assets are dependencies.

## Verification

- Full Window-PPTX Python suite: 505 passing tests in 274.44 seconds.
- Skillbird format check: 23 skills checked, no issues.
- Python compilation and diff whitespace checks: pass.
- Six calibration scenarios: 8-10 fact-backed slides, 5-7 layout families, three enhanced direction candidates, full fact retention, full Recording-COM native editability, and no quality-v2 hard-gate failures. Product launch deliberately exercised two image-to-native fallbacks.
- 180-trial manifest: deterministic and schema-valid across 15 scenarios, 3 arms, 2 ordinary-model providers, and 2 repeats. Full-v5 requires strict BriefPlan JSON plus identity-bound FactStore, NarrativePlan, direction, DeckPlan, compiled plan, RenderPlan, QA, provider, response, and artifact hashes.

## Not Yet Proven

The implementation is not evidence that ordinary models already equal a senior designer. Real portable PPTX/PDF/PNG visual review, both ordinary-model benchmark runs, the formal 180-trial benchmark, blind human review, and sampled PowerPoint certification remain unavailable. Phase 27.1 evidence is therefore incomplete and explicitly carried into Phases 27.2-29; v5.0 remains unshipped.
