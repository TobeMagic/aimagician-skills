# Phase 27.1 Discussion Log

> **Supersession note (2026-07-21):** The decisions below are the historical Phase 27.1 boundary. The user later chose PptxGenJS for governed daily rendering, LibreOffice/Poppler for daily proof, HTML for proof/QA only, and PowerPoint for explicit legacy use plus sampled certification. The rejection of copied Huashu HTML-to-PPTX runtime remains in force.

## Decisions

- The user accepted the decision-complete implementation plan and requested implementation.
- Huashu principles may be adapted for a combined result, while its engine, assets, named styles, and prompt text are not adopted.
- The active v5.0 milestone is extended with Phase 27.1 before the benchmark is re-frozen.

## Assumptions

- Ordinary-model stability and client-ready editable PPTX quality take precedence over maximal visual freedom.
- Native PowerPoint and deterministic registry behavior remain required even when a visually richer HTML path exists.
- Interactive direction choice is optional; unattended deterministic safe selection is the default.

## Rejected Options

- Replacing COM/native rendering with HTML-to-PPTX.
- Adding a fourth benchmark arm after the three-arm protocol was accepted.
- Treating incomplete pre-Huashu runs as a baseline PASS.
- Deleting or repurposing the root DeckPlan files.

## Deferred Work

- Hosted template gallery, generative-image production, editable native SVG conversion, PPT/PPTM output, and broad third-party template import remain outside Phase 27.1.
