# Phase 27.1 Context: Huashu Design Reference Assimilation

> **Supersession note (2026-07-21):** This file records the context used for the Phase 27.1 implementation. Phase 27.2 later made DeckPlan/RenderPlan—not the Windows renderer—the canonical cross-backend boundary. PptxGenJS is now the governed daily backend; COM is retained for legacy routes and sampled certification.

## Implementation Decisions

- Historical decision, superseded for governed daily delivery: preserve DeckPlan v1 and the Windows-native renderer as canonical.
- Current decision: preserve DeckPlan v1 and RenderPlan as canonical, add PptxGenJS as the default governed renderer, and keep COM as an explicit capability-gated adapter.
- Add strict FactStore, BriefPlan, NarrativePlan, BrandSpec, art-direction, decision-trace, quality-report-v2, and repair-log-v2 contracts.
- Build three stable safe/editorial/expressive candidates from twelve neutral profiles; never use random time-based selection.
- Use one pre-render and one post-render repair round with immutable facts and rollback.

## Existing Patterns To Preserve

- `additionalProperties: false`, semantic-only model input, normalized public models followed by revalidation, deterministic registry loaders, stable tie-breaks, recording fake COM, transactional candidate saving, and exact source hashes.
- Existing themes, layouts, components, asset provenance, native charts/tables/diagrams, and quality v1 readers remain compatible.

## Allowed Scope

- `skills/owned/window-pptx`, its tests, v5 benchmark files, Phase 27.1/28/29 planning artifacts, and generated evidence directories.
- Read-only review of the pinned Huashu subtree and read-only OpenCode audits restricted to the repository root.

## Forbidden Scope

- The two root DeckPlan JSON files; unmanaged user files; secrets; CLI global configuration; Huashu code/media except the MIT LICENSE notice; destructive cleanup; source deck overwrite; arbitrary code, macros, or plugin dispatch.

## Integration And Compatibility

- Existing `--deck-plan` compile/render routes remain supported.
- New BriefPlan routes compile to DeckPlan v1 and backend-neutral RenderPlan. The historical COM pipeline remains compatible; Phase 27.2 adds the default portable pipeline.
- Existing quality-report-v1 and repair-log-v1 readers remain supported; v2 writers are additive.
- Formal benchmark replay pins the legacy engine and new engine separately and rejects mixed fingerprints.

The pre-existing dirty tree is protected by `.planning/snapshots/phase-27.1-pre-huashu/`; 106 files passed a byte-for-byte restore drill. Existing benchmark evidence is `pre-huashu/noncanonical`, and the two root DeckPlan JSON files are excluded user files.
