# Phase 45: Selection-to-Materialization Bridge - Plan 01

**Created:** 2026-07-30
**Status:** Approved
**Requirements:** V6R-MAT-01

## Objective

Connect certified candidate selection to executable native and physical
materializers with complete fail-closed evidence.

## Tasks

### Task 1: Complete the selection contract

**Requirements:** V6R-MAT-01

Carry `base_variant_id` through blueprints, derive a locked selection brief
from governed production content, validate explicit choices, and serialize the
plan and blueprints in generation evidence. Write schema-v1 sidecars named
`template-selection-plan.json` and `slide-blueprints.json` in the generation
audit directory.

### Task 2: Registered-native execution

**Requirements:** V6R-MAT-01

Bind every registered blueprint to the exact compiler/render layout. Emit
planned evidence before rendering and PASS evidence only after exact observed
layout verification. Resolve variants before compile, forbid fallback, compare
one observed RenderSlide per selection, and raise stable `MATERIALIZER_*`
failure codes for unknown variants, wrong engines, mismatch, and incomplete
coverage.

### Task 3: Physical TemplatePack execution

**Requirements:** V6R-MAT-01

Add a bridge around the existing lossless adapter that validates a uniform
physical plan, executes declared bindings, and binds every selected physical
slide to the verified output package and source/output hashes.
Reject multiple spines or mixed materializers. The adapter report plus exact
selection cardinality forms the only physical PASS checkpoint.

### Task 4: Production artifacts and gates

**Requirements:** V6R-MAT-01

Write selection, blueprint, and materialization reports from the CLI. Add
focused fail-closed tests, run regression suites, inspect generated artifacts,
obtain a fresh independent OpenCode audit, and complete only with no unresolved
Blocker or Important.

The materialization sidecar is
`candidate-materialization-report.json`; the generation manifest embeds the
same canonical payload and schema version.

## Rollback And Recovery

Remove the bridge fields and reports to restore the pre-Phase-45 path; source
packs remain immutable. A failed materialization never promotes a candidate
output or PASS evidence.
