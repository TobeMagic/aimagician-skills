# Phase 54: Certified Component Closure Assembly

## Trigger

The clean `gpt-5.6-terra` professional-report author run finished without a
PPTX at `STYLE_CLUSTER_LOCKED_ANCHOR_NO_MATCH`. The runtime correctly found
that the selected cover's whole-page visual family contains no compliant,
capacity-safe four-step delivery surface. Earlier `NO_MATCH` results also
covered two-metric and multi-card evidence pages. This is a library/assembly
capability gap; more prompt iteration must not weaken semantic, capacity,
style, source or provenance gates.

## Goal

Make `component_assembly` mean physical composition, rather than selecting a
region and then importing its complete source slide. An agent may choose a
certified host page and a bounded set of certified component IDs. The runtime
must insert each component's complete native shape closure into a certified
host insertion anchor while preserving native editability.

## Contract

1. Library maintenance emits a hash-bound private component profile per
   component: source page/package/slide fingerprint, complete member shape
   IDs in z-order, its relationship IDs, semantic fields, bounding box,
   allowed host-anchor class and prohibited adaptations. It also emits
   host-anchor profiles with their certified shape reservation and compatible
   component classes. Heuristic shape grouping at client runtime is forbidden.
2. The public composition request records IDs only: one host page candidate
   and zero to three component candidates per beat. It cannot carry a
   coordinate, scale, colour, font, raw XML, raw relationship ID, shape ID or
   private locator. A component is valid only if it and the host are certified,
   style-compatible, suited to the client, semantically appropriate and match
   one published anchor class.
3. The physical adapter resolves profiles privately and emits a locked
   `ComponentImportSpec`: source package/slide fingerprint, member shapes,
   source relationship closure, host anchor fingerprint and host source
   fingerprint. It rejects macros, OLE, script, file, unsafe external and
   unclosed relationship targets before assembly.
4. The physical assembler imports the host page normally, copies each
   component XML group in source z-order, replaces only conflicting native
   non-visual IDs and relationship IDs, maps its internal dependency closure
   into the output OPC package, and appends the members to the host `spTree`.
   It never rasterizes the component or redraws it from geometry.
5. Binding occurs only after the component is present. Each component field is
   subject to the existing fact-store, group-completeness, capacity,
   typography and source-residue gates. Component lineage is recorded beside
   host lineage; mixed-source counts include component provenance without
   allowing components to mask repeated hosts.
6. A component insertion is rejected if it would overlap a non-reserved host
   shape, if its native bbox does not fit the published anchor transform, if
   it has unresolved/dangerous references, or if it would leave a published
   member surface empty.

## Implementation Slices

1. Add internal `ComponentImportSpec` and deterministic XML/relationship
   closure helpers to `window_pptx.physical_assembly`; implement synthetic
   text/shape components first, including cNvPr and relationship-ID collision
   rewrites.
2. Add synthetic PPTX fixtures covering host insertion, group member order,
   editable text, bitmap/chart relationship closure, collision rewriting,
   unsafe relationship rejection and replay stability.
3. Extend catalog maintenance with private component/anchor profiles and make
   `query`/`compose` accept only published component and host IDs.
4. Extend preflight, outline binding, adaptation, lineage, replay and QA for
   component imports. Do not expose private profile content in client files.
5. Re-run the clean professional author from its client-only input pack. The
   model must use the new component route only where a whole page receives a
   truthful `NO_MATCH`. Then create and run the independent academic-defense
   pack through identical gates.

## Acceptance Evidence

- A synthetic output opens in python-pptx and LibreOffice, has native inserted
  shapes/text, has no full-slide raster fallback and has no unresolved or
  unsafe relationship.
- Mutating a source component relationship or host anchor fingerprint fails
  closed before output creation.
- The clean professional and academic authors each derive their own
  narratives and produce separate editable PPTX artifacts whose component and
  host provenance, replay, render and independent blind-review gates pass.
