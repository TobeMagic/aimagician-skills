# Phase 54: Local Runtime Configuration and Clean Codex Acceptance

## Purpose

Run the installed `pptx-studio` Skill against a genuinely clean client request
without copying, committing or exposing Gaojie source packages. This is the
operational bridge between governed local commercial assets and a managed
Codex installation.

## Runtime Contract

1. The local checked-out Skill root is the only development asset authority:
   `skills/owned/pptx-studio/.private`.
2. Private-root precedence is exactly: CLI `--private-root`,
   `PPTX_STUDIO_PRIVATE_ROOT`, `$PPTX_STUDIO_SKILL_ROOT/.private`, then a
   co-installed `.private`. There is no cwd/client-folder search.
3. The catalog carries a manager-generated certification overlay bound to
   `certified-core.json`. Final `deny` pages are blocked at catalog, query,
   planner, composition, preflight and assembly boundaries; a digest mismatch
   makes `runtime-check` fail closed.
4. `runtime-check` writes only aggregate counts and SHA-256 digests. It never
   serializes a private root, source locator, preview or package byte.
   A model-authored substitute report, including a bare `status:"PASS"`, is
   invalid and stops the author run.
5. Skillbird installs public instructions and scripts only. The Codex process
   receives `PPTX_STUDIO_SKILL_ROOT` and `PPTX_STUDIO_MANAGER` pointing to the
   checked-out development Skill, so managed installation does not need a copy
   of commercial assets.

## Clean Acceptance Procedure

1. Create a new temporary client directory with only the hospital finance
   requirement documents, normalized brief and validated narrative ledger.
   Record an initial manifest and fail if any PPTX, preview image, private
   locator or historical output is present.
2. Write `work/runtime-health.json` through `runtime-check`; inspect it for
   safe aggregate evidence only.
3. Sync the public `pptx-studio` Skill to Codex and verify the installed
   instruction digest against the source public files.
4. Run `gpt-5.6-terra` at medium reasoning through the exact staged prompt:
   validate narrative; select an anchor; batch-query certified candidates;
   write a v2 composition plan bound to all narrative beats; compile,
   preflight, adapt and assemble. The model may not draw a freeform deck.
5. Require the output, replay evidence, physical lineage and quality reports
   under client-local `work/` and `output/`; preserve its JSON transcript.
6. Reject and iterate if any command returns a fail/migration report, the
   deck has incomplete beat lineage, fewer than six source packages/five
   categories for a substantive 10+ page deck, more than four pages from one
   source package, or any unsafe/private material appears in the
   client pack.
7. Only then perform exact-SHA PowerPoint canvas and independent blind review.
   These remain release gates, not author self-scoring.
8. After this professional-report case passes, repeat from a separate clean
   client directory for a complete academic-defense brief. Do not copy its
   narrative, candidate IDs, fact store or composition plan from the report
   case; only the public Skill and operator-configured private runtime are shared.

## Failure Handling

- `PPTX_STUDIO_PRIVATE_LIBRARY_UNAVAILABLE`: fix the declared runtime variable;
  do not look for assets in the client directory.
- A runtime report missing positive package/page/observation counts or the
  manager-generated digest fields: reject it as `RUNTIME_EVIDENCE_INVALID`;
  rerun the exact manager command, never repair the JSON by hand.
- Candidate/capacity failure: revise the agent selection plan and re-query;
  do not use arbitrary geometry or a raster fallback.
- Replay mismatch: preserve the artifact and emit `MIGRATION_REQUIRED`; do not
  silently reinterpret it.
- PowerPoint or blind-review failure: retain the evidence, repair only the
  governed plan/slots, and rerun the exact checks on the new SHA.
