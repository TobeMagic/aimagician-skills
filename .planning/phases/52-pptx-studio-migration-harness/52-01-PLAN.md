# Phase 52: PPTX Studio Migration and Agent Workflow — Plan 01

**Created:** 2026-08-12
**Requirements:** V7-SKILL-01, V7-QA-01, V7-MIGRATE-01
**Status:** In Progress

## Objective

Turn Phase 51's ID-only composition/adaptation pair into a physically reused,
native-editable PPTX; put the governed client discussion-to-delivery workflow
under `pptx-studio`; and move the public identity only after the migrated
source and installed skill pass parity checks.

## Non-Goals

- Publishing private Gaojie packages, previews, paths, credentials or client data.
- Letting an agent write coordinates, fonts, colors, OOXML or post-assembly shapes.
- Treating Windows COM as a production dependency.
- Calling Phase 53's real 15-slide Codex acceptance complete in this phase.

## Tasks

### Task 1: Compile ID-only plans into importer-native source/slot bindings

**Requirements:** V7-MIGRATE-01, V7-QA-01
**Depends on:** Phase 50 catalog and Phase 51 plans
**Allowed files:** `scripts/pptx_studio/physical_adapter.py`, CLI, schemas, focused tests
**Forbidden files:** private bytes, client folders, source template mutation

1. Resolve package hashes only under the configured private active-source root.
2. Recompute source-slide fingerprint and native slot graph from the resolved PPTX.
3. Convert catalog page IDs to legacy importer identity locally; preserve catalog IDs
   only in value-free provenance.
4. Bind every native text slot to either an approved fact or immutable source text;
   bind images only through hash-checked client assets and cover crop.
5. Invoke the cross-package OPC importer with dependency closure, portable opening and
   output-size checks enabled.

**Acceptance:** a generated fixture produces an editable PPTX, replaces text and image,
and records package/slide/slot lineage without literal client copy or private paths.

### Task 2: Bind values to adaptation plans and attach bounded QA/repair evidence

**Requirements:** V7-QA-01
**Depends on:** Task 1
**Allowed files:** `adaptation.py`, plan schema, `qa.py`, CLI, focused tests
**Forbidden files:** model-written repair code, source mutation, arbitrary post-hoc geometry

1. Add a value-registry SHA to the adaptation plan so an ID-only plan cannot be
   replayed with changed client copy.
2. Run physical importer verification, existing rule QA and plan-aware density,
   overlap, repetition, style and lineage checks as one release report.
3. Document the only automatic repair: importer-owned `shrink-to-fit` on an approved
   replacement slot. All remaining blockers require replan/reassembly.
4. Add failure fixtures for template/hash drift, changed fact values and placeholders.

**Acceptance:** QA emits a stable pass/fail result, detects deliberate blocker fixtures,
and never alters source geometry or unbound content.

### Task 3: Create concise public `pptx-studio` agent contract and migrate identity

**Requirements:** V7-SKILL-01, V7-MIGRATE-01
**Depends on:** Tasks 1–2
**Allowed files:** owned skill metadata/evals, installer catalog/config, tests
**Forbidden files:** compatibility shim after flag day, stale installed copy, private assets

1. Create concise instructions for discuss → brief lock → art direction → bounded
   retrieval → composition → adaptation → assembly → QA → independent review.
2. Add evals for incomplete briefs, normal work report, exact-deck use and raw-design
   injection.
3. Move production source identity to `pptx-studio`, update installer discovery and
   verify source/install digest parity.
4. Delete the `window-pptx` production tree only after the new source/install and
   focused physical assembly tests pass; do not leave a compatibility shell.

**Acceptance:** no production entry point uses the old identity and the installed Skill
matches the source digest exactly.

## Rollback And Recovery

- Until flag-day migration, revert only the new adapter/QA/Skill commits; source packages
  are never changed.
- After migration, restore the last pre-migration Git commit rather than creating an old
  identity compatibility shim.
