# Phase 53: Clean-Room Work-Report Acceptance and Release — Plan

**Status:** Accepted
**Requirements:** V7-ACCEPT-01, V7-RELEASE-01

## Objective

Produce and independently release-verify one clean-room 15-page hospital
finance annual report authored by a fresh capable-model Codex session under the
installed governed PPTX Studio Skill.

## Tasks

1. Create and inventory a clean 15-page hospital-finance client brief folder.
2. Install the current `pptx-studio` Skill in Codex; lock the source/install digest.
3. Run the exact `gpt-5.6-terra` medium Codex command with a task prompt that
   forbids freeform/raster fallback and requires plans, assembly and QA.
4. Independently inspect output, lineage and report hashes; render delivery pages.
5. Perform three independent anonymous visual reviews and a frozen audit; repair and
   rerun if any release gate fails.

## Requirement Mapping

| Requirement | Tasks | Observable evidence |
|---|---|---|
| V7-ACCEPT-01 | 1–4 | Clean inventory, immutable Codex transcript, exactly 15 physical editable slides and complete value-free lineage. |
| V7-RELEASE-01 | 2–5 | Source/install digest parity, exact-file QA, three isolated visual reviews and frozen audit with no Blocker/Important. |

## Verification

```bash
find <clean-folder> -type f | sort
codex exec --dangerously-bypass-approvals-and-sandbox \
  -c 'model_provider="OpenAI"' -c 'model_reasoning_effort="medium"' \
  --cd <clean-folder> -m gpt-5.6-terra --json '<prompt>'
```

## Rollback And Recovery

- If Codex emits an invalid or ungoverned plan, preserve its JSON transcript as
  failed evidence, discard only the client-local generated output and retry
  with a narrowed production prompt. Do not modify private source packages.
- If output QA fails, repair only by re-planning/re-assembling; do not patch
  native geometry or OOXML after assembly.
- If installation parity fails, reinstall from the frozen source after fixing
  the public copy filter; do not reintroduce a private-library copy.
