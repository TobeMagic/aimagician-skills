# Plan 01: Backend Contract, PptxGenJS, and Deterministic Package

**Requirements:** V5-PORT-01, V5-PORT-02, V5-PORT-03
**Status:** Accepted

## Objective

Implement the backend-neutral contract and a pinned PptxGenJS renderer that produces deterministic, identity-bound, native-editable PPTX without invoking COM.

## Tasks

- [x] Add failing Python and Node tests for backend capabilities, selection, unsupported-feature rejection, object identity, object/data parity, page ratios, and deterministic bytes.
- [x] Add stable backend capability/result models and compute required capabilities from RenderPlan before candidate or process mutation.
- [x] Add a fixed-schema Python-to-Node worker boundary; the model never authors or executes JavaScript.
- [x] Pin PptxGenJS 4.0.1 and map registered text, shape, image, table, chart, diagram, note, link, master, and footer items to native objects.
- [x] Persist `objectName` and structured `altText` identity for every governed object; express portable diagram groups as metadata-bound editable children.
- [x] Normalize core properties and ZIP metadata deterministically.
- [x] Integrate `auto|pptxgenjs|com` selection without weakening explicit legacy COM routes or transaction guards.
- [x] Verify two same-input runs are byte-identical and that unsupported required capabilities fail before filesystem/process mutation.

## Verification

- Focused backend, worker, mapping, page-ratio, identity, capability, transaction, and determinism tests pass.
- Node typecheck/test and Python compile checks pass.
- Existing COM and Recording-COM regression tests remain green.
- A COM-denied portable smoke produces a valid deterministic candidate without `POWERPNT.EXE` activity.

## Rollback And Recovery

PptxGenJS is additive behind an explicit backend selection. Keep the COM adapter intact for rollback, but never use it as an implicit `auto` fallback. A failed normalization or render remains a candidate and cannot be promoted.
